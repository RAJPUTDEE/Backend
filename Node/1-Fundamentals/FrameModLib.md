/*
 MODULES
 -------
 A module is the smallest unit of code that can be reused, typically contained in a single file.
 It is a self-contained code, encapsulates functionality and can be imported.
 Modules help to organize code, promote reusability, and maintain separation of concerns.
 To organize code by grouping related functions, classes or variables together.
 Developers import it.

 LIBRARY
 -------
 A library is a collection of modules or packages bundled together to provide a specific functionality.
 Libraries are often created by third-party developers and can be imported into your projects to save time and effort.
 Developers call specific functions or classes from the library to perform tasks without needing to write the code from scratch.

 FRAMEWORK
 ---------
 A framework is a comprehensive environment that provides a structural foundation or "skeleton"(kind of blueprint) for an entire application.
 It provides a set of conventions and guidelines for developers to follow, often enforcing a specific way of organizing code and handling common tasks.
 A kind of MVC (Model-View-Controller) architecture, that dictates how an application should be structured and built, providing built-in tools for routing, security, and database management.
 In MVC architecture, the Model represents the data and business logic, the View is responsible for the user interface, and the Controller handles user input and interactions between the Model and View.
 
 Inversion of Control (IoC) occurs here. The framework is in charge; it calls your code at specific points in its lifecycle,
 rather than you calling the framework. This means that the framework dictates the flow of the application, and you write code that fits into that flow.
 
*/
